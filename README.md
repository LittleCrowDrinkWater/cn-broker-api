# cn-broker-api

> **A股量化交易**的券商接口层：让策略程序用 HTTP **自动下单**，不必自己去碰桌面客户端。

把一台 Windows 机器上的**桌面券商客户端**包成一个券商风格的本地 HTTP 接口。

你的策略程序面对的是 `POST /v1/orders`、`GET /v1/positions` 这样的东西，和对接互联网券商
OpenAPI 没有区别。客户端进程在不在、交易登没登、行情断没断、厂商页面被升级冲掉没有——
都是这个服务的事，不再是策略程序的事。

```
       策略程序 ──HTTP──▶ cn-broker-api ──▶ 桌面客户端 ──▶ 券商柜台
     （可移植）           （这个仓库）      （只能在这台机器上）
```

**这份 README 按「照着做」的顺序写**：先是开始之前必须知道的三件事，然后五步把它装起来跑通，
然后是日常调用和排查。想改代码的话，最后一节〈设计说明〉讲的是每处为什么这么写。

## 开始之前

三件事，看完再决定要不要往下走。

### 一、它发的是真委托

`POST /v1/orders` 一路走到**券商柜台**。`driver.name = "tdxquant"` 时**受理即真发出**，
用的是真实资金账户，包括融资买入、融券卖出、买券还券、卖券还款这一族信用委托。

**唯一安全的试法是把 `driver.name` 改成 `paper`**（纸面驱动，压根不连客户端）。
没有第三档"演练模式"——一个看起来像真的假模式，只会让人在真账户上放松。

2026-08-22 真机实测过这条链的每一段：委托打到底会停在客户端的**信号队列**里等确认
（服务回 `202`），**自动确认补丁点掉它之后，它就是柜台上的一笔真委托**。

### 二、实测环境只有一套

| | 实测的那一套 |
|---|---|
| 券商 | **平安证券** |
| 客户端 | 通达信「开心果整合版」（第三方整合发行版） |
| 账户类型 | 信用（两融）；普通账户的路径没有系统验过 |

换一家券商、换一个客户端版本，**这份文档里每一条口径都要自己重新验一遍**。
尤其是**自动确认补丁那一整块是照着平安的实现写的**——二次确认由券商决定，不是通达信的
本地选项。别家可能压根没有这道确认，也可能有但页面和字段完全不同（详见第 3 步）。

### 三、它会替你输交易密码

券商在密码连续输错之后会怎么做（锁多久、要不要人工解锁）**各家不同、本项目未核实**。
所以有两个闸，方向不同、刻意不合并：

| 闸 | 数什么 | 什么时候清零 | 防的是 |
|---|---|---|---|
| 连续失败 **3** 次就停手 | 连续没成功的提交 | **成功登录时**，不按天 | 券商锁定账户 |
| 每天最多 **10** 次 | 当天提交总数（含成功） | 每天午夜 | 我们自己的代码循环提交 |

**认不准就中止，失败绝不重试。** 调大 `max_consecutive_failures` 之前先向你的券商确认后果。

另外两点：它会**修改客户端安装目录里的页面文件**（自动确认补丁，会先备份）；
它只监听 `127.0.0.1` 且**不可配置**——这个端口能下单，让它监听外网不该是一个"选项"。

## 你需要准备什么

- **Windows**（必须；它要枚举窗口、往密码框里打字、抓窗口位图）
- **Python 3.11 以上**（`tomllib` 要标准库自带）
- **一份带量化模块的通达信客户端** —— 这一条最容易卡住，往下看

### 客户端要哪一版

本机实测跑通的是**平安证券 + 通达信「开心果整合版」**，后者是第三方整合发行版，
不是券商官方分发的那几个。

**怎么认**：安装目录里有 `开心果顶栏` 目录和 `版本说明必看.txt`；客户端自带的下载入口指向
`www.70822.com`。本机装在 `D:\Common\TDXV2026X64`。

两个进程，缺一不可：

| 进程 | 位数 | 干什么 |
|---|---|---|
| `Tdxw.exe` | x64 | 主程序。**量化模块和本地 JSON-RPC 端口 17709 是它开的**——本服务的全部调用都打这里 |
| `NewTc\TC.exe` | 32 位 | 交易模块。真正持有交易登录态、真正把委托送去柜台的是它 |

**为什么非要整合版**：券商自己分发的安装包里，**量化模块与交易模块凑不齐**——装 32 位的
那份有交易、没量化模块；装 64 位的那份有量化模块、没交易。只有整合版把两个装在一起，
这个服务才有东西可对接。

第三方整合版**不是券商官方分发**，它自己的免责声明也这么写，合规性与安全性自行判断。
厂商官方的量化平台只支持财富趋势自家版本，券商版设计上就没有量化模块。

## 第 1 步 · 装上，先用纸面驱动跑通

```bash
git clone <this repo> cn-broker-api
cd cn-broker-api
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

写一份最小配置，**放在仓库之外**（下一步细说），先用纸面驱动：

```toml
[server]
port = 17710
state_dir = "D:/your-state-dir/cn-broker-api-state"

[driver]
name = "paper"          # 不连任何东西
```

起服务：

```bash
set CN_BROKER_API_CONFIG=D:\path\to\cn-broker-api.toml
.venv\Scripts\python -m cn_broker_api
```

首次启动会在状态目录里生成一个 token 并**把路径打印出来**。所有接口调用都要带
`Authorization: Bearer <token>`。

确认通了：

```bash
curl -H "Authorization: Bearer <token>" http://127.0.0.1:17710/v1/meta
```

浏览器打开 `http://127.0.0.1:17710/` 是诊断页（单文件，无构建步骤）。

**纸面驱动值得多跑一会儿。** 它还是「是契约错还是驱动错」的判别工具：同一个请求打两个
驱动，一个对一个错，问题就在驱动。但它**不模拟撮合、不模拟成交、不模拟拒单**——
那几件事只有在真柜台上才有意义，假件在这些地方越像越危险。

## 第 2 步 · 写正式配置

复制 `config.example.toml` 到**仓库之外**，改成你机器的实际情况。默认位置是仓库的上一级
（`../cn-broker-api.toml`，刚好在 git 视野之外），也可以放任意位置然后指环境变量：

```bash
set CN_BROKER_API_CONFIG=D:\path\to\cn-broker-api.toml
```

**「有哪些可配置」看两处，它们都不会和代码分叉：**

1. **`config.example.toml`** —— 全部配置项都在里面，每项写了用途、默认值、以及那个默认值
   的由来。有一条用例盯着它：新加了配置项但忘了写进模板，测试会红。
2. **服务启动时打印的那份清单** —— 生效值全列一遍，在**吃默认值**的项前面标一个 `~`：

```
    driver.tdxquant.tdx_home                     D:\Common\TDXV2026X64
  ~ watchdog.enabled                             false
```

看这个标记，因为**漏写一项**和**写了一项写错值**现象完全不同，而只看最终值分不出这两种。
诊断页上有同一份清单。

**凭据不要写进配置文件。** 交易密码有两条路：`cred_source = "request"` ＝调用方随请求
下发，服务不落盘；`"file"` ＝服务自己读一个仓库外的凭据文件。两种都不经过 TOML——
配置是给人读的、要进版本控制的东西。

仓库 `.gitignore` 挡掉了 `*.toml`（只放行示例）、token、state 目录、以及**截图**
（窗口位图会把账号、持仓、资产原样拍进去）。

## 第 3 步 · 准备客户端

**这一步的每一件事，漏掉的表现都是「那天早上什么都没发生」，而不是报错。** 按顺序做。

### 3.1 先手动登一次，行情和交易各一次

让客户端把资金账号记下来。本服务对登录框里的账号只**核对**、不选择——那个下拉是厂商自绘
控件、没有窗口句柄，认错的代价是拿密码去试另一个账号，所以宁可不动手。

### 3.2 在客户端设置里打开「自动登录」

不打开的话，自动拉起之后会停在行情登录框上，而本服务**不填行情密码**（它只管交易密码）。

**它只登行情，交易那一半不会跟着起。** 主程序开了自动登录之后，启动只登行情；交易模块
要人在界面上点一下【交易】才拉起——于是会卡在"既没登上、也没有登录框"的僵局里
（实测等 120 秒也不弹框）。所以 `TC.exe` 由本服务自己拉，它列在配方的第二个位置。

### 3.3 配置里填上 `tdx_home`

```toml
[driver]
name = "tdxquant"

[driver.tdxquant]
tdx_home = "D:/Common/TDXV2026X64"    # 客户端安装目录
mcp_url  = "http://127.0.0.1:17709"   # 主程序开的那个本地 JSON-RPC 端口
```

`tdx_home` 是**唯一出处**：`PYPlugins` 路径、要打补丁的页面文件、两个可执行文件全从它推
出来。填错的现象是自检报**「补丁没打」**，不是「路径不对」——"文件不在"和"补丁不在"
在检查那一层长得一样。

### 3.4 装自动确认补丁

> **这一步是平安证券专属的**，别家券商见本节末尾。

实盘账户上**每一笔量化委托都先回**「已发送信号至客户端，待用户确认！」，没有补丁就得人去点。
补丁改的是客户端安装目录里的页面文件（会先备份）。

```bash
# 看现在什么状态（读的是服务用的那份配置，tdx_home 从那里来）
.venv\Scripts\python -m cn_broker_api.drivers.tdxquant.autoconfirm --status

# 先演练：点的是【取消】，整条链路照走一遍但一笔单都不会报出去
.venv\Scripts\python -m cn_broker_api.drivers.tdxquant.autoconfirm --apply --mode cancel

# 确认演练时它真的动了手，再换生产档
.venv\Scripts\python -m cn_broker_api.drivers.tdxquant.autoconfirm --apply --mode send --account 你的资金账号

# 卸掉：用备份把页面还原回去，并删掉旁挂配置
.venv\Scripts\python -m cn_broker_api.drivers.tdxquant.autoconfirm --remove
```

**`--mode` 默认就是 `cancel`（演练档），先用它。** 用同一条链上无害的那个按钮验通整条
链——补丁认不认得出信号行、点不点得动、账号闸对不对，演练档全都验得到，而验错的代价只是
一笔委托被取消掉。确认无误再换 `send`。（`--anytime` 放开时段闸，只给演练用，生产别加。）

**它有三道闸，报单前要知道自己落在哪一格：**

- **时段闸**，默认 `09:15–11:35` / `12:55–15:05`。**午休那个缺口是真的缺口**——落在
  11:35–12:55 之间的委托它不会点。
- **行龄 ≤90 秒**：防「早上没人确认的陈旧信号，下午被顺手一起发出去」，这是最危险的一格。
  过了 90 秒它**不会补发**，那笔信号就一直躺在队列里。
- **单笔上限**（股数与金额）与**账号核对**。

⇒ 你今天要报单的那几个时刻在不在覆盖里，别猜，问它：

```
GET /v1/health?account=…&account_type=…&need_times=09:23,09:26,09:35,14:57
```

**客户端升级会把补丁冲掉。** 所以自检把「补丁还在不在」做成一项检查，而不是假设它一直在。

**换券商这一整块都要重写。** 二次确认由**券商**决定，不是通达信的本地选项（证据在
`drivers/tdxquant/autoconfirm.py` 的模块 docstring 里，五条）。补丁里一切具体的东西——
页面路径 `webs/cfg/aireq.html`、组件选择器 `.ai-req`、宿主方法 `GetAutoJyReqList` /
`sendautojy`、行上的 `ZH` / `STATE` / `REQ_ID` / `TIME` 这几列——都是从**平安下发的那一份
HTML** 上读出来的。三种可能，处置各不相同：

1. **那家根本不做二次确认** ⇒ 不需要补丁，`order_stock` 直接回 `2`，服务永远不会回 `202`。
2. **做，但页面/字段不一样** ⇒ 把那份 HTML 重读一遍，照现在这个形状写一份新的。
   机制（旁挂配置、五道闸、演练档、幂等）可以照抄，**选择器与列名必须重新认**。
3. **做，且客户端不给自动化的口子** ⇒ 这条路走不通，只能人工点，或者换客户端。

**不实现也能用**：补丁不在时服务**拒绝受理**（`503`），委托不会静默躺在队列里等人点。

## 第 4 步 · 换成真驱动，验一遍

把 `driver.name` 改成 `tdxquant`，重启服务，然后**按这个顺序**验：

```bash
# ① 通道自检：四项一起看，refresh=true 才是真去探
curl -H "Authorization: Bearer <token>" \
  "http://127.0.0.1:17710/v1/health/refresh?account=你的账号&account_type=CREDIT" -X POST
```

四项全绿长这样：

```
✅ 客户端进程      127.0.0.1:17709 通
✅ 交易账号登录    权益 xxxxx.xx / 可用 xxxxx.xx
✅ 客户端行情      000001.SZ 现价 11.41（买一 11.41 / 卖一 11.42）
✅ 自动确认补丁    aireq.html 已引 tq_autosend.js；档位 send、账号 …、行龄 ≤90s
```

```bash
# ② 只读路径：账户、持仓、可卖量、当日委托
curl -H "Authorization: Bearer <token>" \
  "http://127.0.0.1:17710/v1/account?account=你的账号&account_type=CREDIT"
```

③ 最后才是报单。**第一笔请挑一个不可能成交的价**（例如买入挂跌停价、100 股）：
价格合法所以拿得到柜台的真实裁决，但只有跌停才会成交。发完**回柜台看委托簿**确认事实，
别只看返回值。

## 第 5 步 · 装成计划任务（长期无人值守）

**不能做 Windows 服务，也不能进容器**：这个服务要枚举窗口、往密码框里打字、抓窗口位图，
而 Windows 服务跑在会话 0、容器里根本看不到桌面。它必须跑在**交互桌面会话**里。

⇒ 用**登录时触发的计划任务**：

```powershell
powershell -ExecutionPolicy Bypass -File .\install_task.ps1 -ConfigPath D:\path\to\cn-broker-api.toml -Start
powershell -ExecutionPolicy Bypass -File .\install_task.ps1 -Uninstall
```

**不装的话它就只是一个你手敲起来的进程，机器重启之后没人把它拉起来。**

为什么是计划任务而不是启动文件夹：计划任务有「上次运行结果」这一栏（配置写错了退出码就是
2，一眼能看见）、能用 `schtasks /run` 手动触发一次，也不会被谁清理开始菜单时顺手带走。

**分工：计划任务保证本服务活着，看门狗保证客户端活着。** 两层各管一层。

**日常部署 = `git pull` + 重启。** 没有编译、没有打包、没有安装器。随时重启是安全的：
额度都落盘、`/v1/session/ensure` 幂等。

## 日常使用

### 接口一览

契约是 `TradingPort` 的 HTTP 投影，不是厂商接口的一对一映射。厂商那套有 70 多个函数，
其中公式引擎、往客户端界面写回、我们自有更好来源的财务统计都不投影出来——
**暴露的是要用的，不是能做的**。

当前契约版本 **2**。调用方启动时校 `/v1/meta` 的 `contract`，不匹配**直接拒跑，不做兼容适配**。

```
运维
GET    /v1/meta                    契约版本 / 驱动名 / 能力清单
GET    /v1/health                  结构化检查项（缓存 + 年龄，便宜）
POST   /v1/health/refresh          强制重探（要连客户端，只在动手前打）
POST   /v1/session/ensure          把客户端弄到「交易通道可用」。幂等、单飞
GET    /v1/jobs/{id}               上一步的进度与终态
GET    /v1/state                   诊断页要的：额度、上次登录、看门狗、当前生效配置
GET    /                           诊断页（单文件，无构建步骤）

交易（账户维度作为业务字段传：account + account_type，不放 header）
POST   /v1/orders                  下单（含 credit_kind：融资买入 / 卖券还款那一族）
DELETE /v1/orders/{order_id}       撤单（内部含「撤完再读一次、按事实定终态」整段循环）
GET    /v1/orders/{order_id}       单笔委托（order: null ＝不在当日委托簿里）
GET    /v1/orders                  当日全部委托（对账用）
GET    /v1/positions               持仓
GET    /v1/positions/sellable      可卖量（三态口径最要紧的一处）
GET    /v1/account                 资产

行情与静态数据（客户端自己那条行情，报单会被它的状态挡住）
GET    /v1/quotes?codes=a,b[&depth=true]   快照：现价/昨收/买一卖一，depth 再加五档含挂单量
GET    /v1/prices?codes=a,b                一次调用拿一批的现价/昨收/成交量（无盘口）
GET    /v1/klines?codes=..&period=1d&count=N   最近 N 根 K 线（refresh=true 先刷缓存）
GET    /v1/limit-status?codes=a,b          封板状态：封单量、首末封板时刻、开板次数
GET    /v1/dividends/{code}?start=&end=    除权除息事件清单
GET    /v1/instruments/{code}              标的静态信息（margin_target 三态）

排查
POST   /v1/session/minimize        收起客户端窗口
GET    /v1/diag/screenshot         当时那个窗口的位图（PNG，不落盘）
```

### 调用方必须做对的三件事

这三条不是风格建议。每一条做错都不会当场报错，而是过几天以某种很贵的形式出现。

**① 查询是三态，不是两态。** 「查不到」和「真的没有」必须分得开：

```json
{"known": true,  "rows": []}            ← 真的空仓 / 今天真的没有委托
{"known": false, "reason": "…"}         ← 判不了
```

把两者揉成一个，症状不是报错——是某天早上对账把持仓账本整表删了、执行侧从零重新建仓。
**传输层失败**（连不上、超时、协议错）才走非 2xx。

**② 下单的每个状态码处置都不同，不许收成一种。**

| 码 | 事实 | 你该做什么 |
|---|---|---|
| `201` | 真报进柜台了 | 正常收尾 |
| `202` | 收下了、**结果还没定**（推给客户端等确认） | **回柜台重新观测**，绝不当拒单 |
| `409` | 定性拒单，原因已知 | 据此记名单 / 补位 |
| `400` | 字段不合法＝**你这侧的 bug**，这一趟什么都没发生 | 改代码，别重试 |
| `501` | 这个驱动没这个能力 | 拒跑，别静默降级 |
| `503` | 通道不可用（含「补丁不在所以不受理」） | 去看自检，**不是柜台的问题** |
| `504` | 状态未知 | **回柜台重新观测**，别重发 |

`400` 与 `503` 最容易混：前者是"请求本身就不对"（方向配反的信用委托、`size=0`），
后者是"客户端没开、交易没登"。报错报成后者，排查会从错的一头开始。

把 `202` 当拒单处置过一次的代价是：柜台已经全部成交，而我们记成失败。

**③「我发了撤单」与「这笔没成交」是两件事**，中间隔着一场会输的比赛。撤单在服务内部是
「提交 → 重查 → **撤完再读一次、按事实定终态**」的一整段，调用方只看最终事实。

### 行情那几个端点的四条口径（都是实测出来的，别靠猜）

1. **不带账户维度、也不要交易登录**：这几个厂商函数不认账户 ⇒ 交易没登也能用，
   而这恰恰是交易登录出问题时最需要能看的东西。
2. **K 线只能取「最近 N 根」**：给了起止区间，厂商只回总数、行是空的（猜过三种分页参数名
   都不行）⇒ **这条路不是历史回补的路**。
3. **分钟线不刷缓存基本就是空的** ⇒ 要分钟线带 `refresh=true`（慢几秒）。
4. **单位在同一个客户端里就不统一**：K 线的成交量是**股**、成交额是**万元**；
   `/v1/prices` 与快照的成交量是**手**。所以每个响应自带 `units`，别让调用方去记。

### 看门狗：要不要开

盯着客户端进程在不在，掉了就拉起来。**默认关**（`watchdog.enabled = false`）——它会真起进程。

| | |
|---|---|
| **做** | 每隔一会儿枚举一次进程，配方里该在跑而没在跑的，拉起来 |
| **不做①** | **绝不填密码**。交易登录仍然只由 `POST /v1/session/ensure` 触发 |
| **不做②** | **绝不 kill**。只在「进程不存在」时拉起 |
| **不做③** | **一次只拉一个**。两个都缺时先拉主程序，下次醒来再看交易模块 |

- **不填密码**是因为密码额度有限，而看门狗每分钟醒一次——让它去登录，就是在没人看着的时候
  把额度烧掉。⇒ 看门狗保证的是**进程活着**，不是**通道可用**，这两件事中间还隔着三道门。
- **不 kill** 是因为进程还活着但没响应时把它杀掉重启，会打断正在飞的委托。
  「没响应」和「没进程」是两件事，它只处理后者。
- **一次只拉一个**是因为客户端还在初始化就又弹一个窗口，而登录那侧的第一步是「先分类是哪道
  门」——两道门同时在场正是那一步最容易认错的场面。

两个闸：**时段闸**（默认 08:40~15:10、只工作日）和**每日拉起次数上限**（默认 3，防
「起来就自己退」的死循环）。次数落盘，重启服务不会清零。

时段闸**刻意不判节假日**：本服务不碰数据库、不该有交易日历这个依赖。节假日多起一次客户端
的代价是桌面上多一个窗口；引一份日历进来的代价是给这个只该说 HTTP 的服务加一个数据依赖。

## 出问题了怎么查

先开诊断页 `http://127.0.0.1:17710/`：额度、上次登录、看门狗、生效配置、四项检查都在上面。
要看客户端当时到底长什么样，`GET /v1/diag/screenshot` 给你那个窗口的位图。

| 现象 | 多半是什么 | 怎么办 |
|---|---|---|
| 调用回 `401` | token 不对 | 状态目录里的 `token.txt`，首次启动时也打印过 |
| 服务起来就退，退出码 2 | 配置有问题 | 计划任务跑的是 `pythonw`（没有控制台，stderr 被丢掉）；用带控制台的解释器手跑一次就能看见那行人话 |
| 自检「客户端进程」红 | `Tdxw.exe` 没起来 | `POST /v1/session/ensure`，或打开看门狗 |
| 自检「交易账号登录」红，说**「资金账户未登录或不存在」** | **多半不是没登录，是账号与类别不成对** | 信用户要 `account_type=CREDIT`。厂商按 (账号, 类别) 找句柄，配错的报错文案和没登录一模一样 |
| 自检「客户端行情」红 | 行情连接断了，或还没到连续竞价 | 行情断**只挡下单**，查询照常通。集合竞价前现价本来就是 0，那不判红 |
| 自检「自动确认补丁」红，说找不到页面 | `tdx_home` 填错，或客户端升级把补丁冲掉了 | `autoconfirm --status` 一眼看清 |
| 自检说 `hours 没覆盖 xx:xx` | 补丁的时段闸没盖住你要报单的时刻 | 要么 `--apply` 时调 `hours`，要么把报单时刻挪进覆盖区 |
| 下单一直回 `202`，委托躺在队列里 | 补丁没在工作：落在午休缺口 / 行龄超 90 秒 / 账号或上限对不上 | `autoconfirm --status`。超过 90 秒它**不会补发**，得人去点或撤掉 |
| 下单回 `503` | 通道不可用（客户端没开 / 交易没登 / 补丁不在） | 这是运维问题，**别去查柜台**，去看自检 |
| 下单回 `504` | 状态未知 | **回柜台重新观测**。读超时不代表没报出去，重发会变双份 |
| 查询回 `known: false` | 判不了 | **别当成空结果**，这一轮别改你的账本 |
| 客户端起来了，但交易模块没起 | 自动登录只登行情 | 正常现象，`TC.exe` 由本服务拉；手动的话在界面上点一下【交易】 |
| 机器重启后早上什么都没发生 | 服务没装成计划任务 | 第 5 步 |
| 登录被拒，说额度用完 | 日闩生效了，**不是故障** | `GET /v1/state` 看剩几次。连续失败那个要**成功登录**才清零，不按天 |

## 设计说明

想改代码再看这一节。这里讲的是每处为什么这么写。

### 架构：两层，接缝只有一处

```
HTTP 层（Flask）              契约 = TradingPort 的投影，与厂商无关
    │
按账户分组的串行队列          一个账户排着的调用全做完，再切下一个账户
    │
Driver                       ← 唯一与厂商有关的一层
    ├── tdxquant             桌面客户端（进程监护 + 登录 + 页面补丁 + 本地 JSON-RPC）
    ├── paper                不连任何东西（联调 / CI / 分清"契约错还是驱动错"）
    └── …                    换厂商＝加一个驱动，HTTP 层一行不改
```

**桌面监护里，机制是代码、配方是数据**：找窗口、填密码框、按颜色找按钮、量星号总宽这些是
**机制**（与厂商无关）；「要保证哪几个进程在跑、可执行文件相对路径、登录框怎么认、
登上了没有用哪个调用验」是**配方**（每个驱动一份数据）。换一个更精简的客户端版本，
多半是加一份配方，不是写新代码。

### 它刻意不做的三件事

- **不能脱开客户端跑。** 交易能力来自客户端进程自己开的本地端口；没有客户端就没有服务端。
  本服务的定位是**让客户端自己起来并登上**，不是绕开它。
- **不做多账户的界面切换。** 交易登录框里的账号只核对、不选择。
- **不做行情研究、不碰数据库、不算因子。** 它只把请求翻译成对客户端的调用。
  依赖表里只有四项，这是刻意的。

### 配置与状态分成两处

| | 配置 | 状态 |
|---|---|---|
| 内容 | 端口、客户端装在哪、选哪个驱动、密码额度、撤单确认超时 | 今天提交过几次密码、连续失败几次、上次登录结果、健康检查缓存 |
| 格式 | TOML | JSON |
| 谁写 | **只有人** | **只有程序** |
| 手改 | 随时 | 绝不 |

选 TOML 的唯一实际理由是**能写注释**。而 `tomllib` 只能读不能写，这个"缺点"正好把纪律焊死：
**服务物理上改不了你的配置**，手写的注释不会被状态写入冲掉。

### 几条反直觉的取舍

**「受理即真发出」。** 自动确认补丁不在、配置关着、时间窗没覆盖当前时刻——这些情况下服务
一律**拒绝受理**（`503`），而不是受理完让委托躺在客户端队列里等人点。所以调用方连"补丁"
这个词都不需要知道。

**健康检查必须便宜。** 「交易账号登录了没」这一项要连客户端、查一次资产，几秒钟。诊断页每
几秒刷一次的话，不缓存等于整天骚扰交易通道 ⇒ `GET /v1/health` 给**缓存 + 年龄**，
`POST /v1/health/refresh` 才真去探。页面上必须显示"数据于 N 秒前"——静默展示旧数据的状态页
比没有更糟。

**行情通不通，判的是「答不答话」而不是「有没有现价」。** 集合竞价还没撮合时现价本来就是 0；
把它一律判红的结果是每天早上一次假警报，而**假警报比不探更糟**——人会学着无视整条自检。

**登录是状态驱动，不是弹框驱动。** 循环是「已登上？→ 有框？→ 处理」，因此天生幂等，
定时任务可以放心反复打。写成「等登录框」会把「本来就好了」读成超时失败。

**不做自动回落。** 一个通道失败了不去偷偷试另一个：两条通道的故障表现完全不同，
自动回落会把"服务挂了"伪装成"柜台拒单"。

**日闩落盘，密码只在内存。** 两者刻意反向——**前者怕丢掉**（放内存的话重启就清零，
"重启三次＝无声无息地试了三次密码"），**后者怕留下来**。

### 部署脚本里三处有讲究的地方

- **不勾「以最高权限运行」**。目标客户端是非提权进程，往它的窗口发消息不需要提权
  （提权只在反方向才是必需的）；而提权跑的话，本服务启动的客户端会继承高完整性级别，
  与人平时手动启动的那一份不是同一套环境。
- **`LogonType Interactive`**。勾成「不管用户是否登录都运行」会把它扔进会话 0，
  那里没有桌面、没有窗口，整套 Win32 自动化一个动作都做不成。
- **装之前先把配置读一遍**。任务里跑的是 `pythonw.exe`（登录时不该弹黑框），而它没有控制台
  ⇒ 配置错误那行 stderr 会被丢掉，能看见的只有「上次运行结果 = 2」。所以安装脚本先用带
  控制台的解释器验一次，让错误现在就以人话的形式出现。

**刻意不声明 DPI 感知**：客户端是 DPI 不感知进程，本服务保持不感知，`GetWindowRect`、
`PrintWindow` 位图、我们 Post 的客户区坐标才落在同一套坐标里。

## 开发

```bash
.venv\Scripts\python -m pytest -q
```

跟客户端有关的用例按平台跳过，所以在 Linux 上也能跑（CI 用纸面驱动）。

**改动纪律**：`drivers/tdxquant/login.py`、`health.py`、`autoconfirm.py` 是从生产环境
**整文件搬过来**的，里面每一处 ``/`` 注释都对应一次真实故障。要动它们之前先读那些注释；
不要为了"看起来更整洁"重排这些代码——那等于把真机验证的结果作废。
