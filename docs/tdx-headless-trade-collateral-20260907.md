## 抓包观察

提交窗口中观察到以下协议流量：

1. 一帧 `client_to_tc` 的 `179` 字节 `rpcfunction`；
2. 随后出现 `tc_to_client` 的 `226` 字节 `callfunction`；
3. 紧接着出现 `4300`、`4292`、`2420` 和 `684` 字节的较大 `rpcfunction`；
4. 同一窗口还出现 `170`、`234`、`218`、`202`、`210` 和 `226` 字节的 `callfunction`，并伴随 `resultType=nullptr` 回执。

撤单窗口再次出现相同类别的大型 RPC 流量。`210`、`226` 等短帧在提交和撤单阶段都会重复，不能单独视为本次订单的业务参数帧。

## 当前判断

- 本次明确的担保买入样本没有在解码后的帧中出现 `000001`、`10.72`、`300` 或委托编号等明文业务字段。
- 用户已确认当天 200 股和 300 股两笔均为担保买入；类型不确定的是最早的历史样本。两笔仍需核对实际调用入口，不能只按帧长度认定为同一种报单请求。
- 业务正文尚未解码，不能确认每个候选帧是否承载订单参数，也不能据此确定压缩或加密算法。

## 后续离线解码结果（更正上述未解码阶段判断）

2026-09-07 继续静态分析后，已使用本地 DLL 中的初始化材料离线还原三份抓包的业务 JSON，未启动客户端或发送交易请求。

- `tdxrpc64.dll` 的 SHA-256 为 `f0855f368084235afa2a5d1d19cd1cce326117b623fe503fb26fc2146fc97a0c`。
- 该版本 RVA `0x14f0` 初始化 Blowfish 的 P/S 表，`0x15c0` 扩展密钥，`0x1860` 按 8 字节块加密，`0x18f0` 解密。编码使用 ECB，每个 32 位字以小端布局存储；补齐 n 字节时使用 n 个 ASCII 数字 n，而非标准 PKCS#7 字节值。
- 密钥初始化由 RVA `0x1100` 引用本地常量；工具仅对上述哈希使用已核验 RVA，不在代码或报告中保存密钥。
- 成功历史抓包解码 160 个正文，拒绝历史抓包 74 个，当日抓包 309 个，合计 543 个，全部通过填充及 JSON 校验。统计针对本次读取到的快照。
- 旧 411 字节帧实际为 `DoLevinGN_909`，参数包含 `zqdm=000001`、`price=10.720000`、`wtsl=100`、`bsflag=0`、`flag=0`。这些数字标志的融资/担保业务语义仍需独立核验。

## 方法与回调配对

对三份快照按 `(method, token)` 与回调中的 `(functionname, token)` 配对，分别得到 72、31、129 组完整配对，共 232 组；没有未匹配回调或待返回调用。`type=0` 的 `nullptr` 是外层 RPC 返回，业务结果应读取另一个方向的 `ReturnValueComp.params.value`。

| 方法 | 已观察到的结果字段及用途 |
|---|---|
| `OperateUser_0` | 登录账户列表，含账户、券商和登录类型信息 |
| `DoLevinGN_803` | 证券数量、可卖数量、成本和市值，属于持仓数据 |
| `DoLevinGN_830` | 可用资金、余额、资产及负债，属于资金数据 |
| `DoLevinGN_807` / `DoLevinGN_822` | 委托数量、价格、成交量和撤单状态；两者的筛选差异尚未确定 |
| `DoLevinGN_909` | 报单回执：`retflag`、`retinfo`、`wtbh` |
| `DoLevinGN_808` | 撤单回执：`success`、`errmsg` |

旧 100 股样本在 JSONL 第 1446 行调用 `DoLevinGN_909`，第 1447 行通过 `ReturnValueComp` 返回 `retflag=1`、非空委托编号、空 `retinfo`。查询结果随后出现对应委托，并最终变为已撤。

当日 200 股、300 股均可从解密后的查询回调观察到：价格 `10.7200`、`bsflag=0`、`cjsl=0`；状态从 `cdflag=0 / kcdflag=1 / 买入@正常委托@` 变为 `cdflag=1 / kcdflag=0 / 买入@已撤@`。这些是本样本的取值，不应扩展为所有状态的通用枚举。

实验副本 `PYPlugins/user/tqcenter.py` 的常量表定义 `CREDIT_BUY=0`、`CREDIT_FIN_BUY=69`，但这是上层接口枚举，尚不能独立证明 HQMP 的 `bsflag/flag` 与之完全等价。旧 100 股单的具体融资/担保类型继续保留为待核验。

后续优先检查 `DoLevinGN_909` 的调用入口及账户映射，先实现直接 TC 的只读会话和回调处理。现有手动操作的结果可查，但缺少对应 HQMP 报单调用；不能把查询结果误作已掌握担保买入请求编码的证据。
