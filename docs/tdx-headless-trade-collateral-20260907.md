### 真实报单与撤单验收（2026-09-08）

操作者明确授权后，纯 Python HQMP 宿主在实验 TC 的已登录融资融券账户中完成了一次真实闭环：

- 标的为平安银行 `000001.SZ`，类型为担保买入，限价 `10.61` 元，数量 `100` 股；
- 报单 `DoLevinGN_909` 返回成功标志和非空委托编号；仓库和本文均不保存完整编号；
- 紧接报单回调发送的第一次 `DoLevinGN_808` 被柜台以“没有对应的委托信息”拒绝；
- 未重复报单，而是用 `DoLevinGN_807` 查询到该笔委托已进入“正常委托”、可撤且成交量为 0；
- 此后再次调用 `DoLevinGN_808`，回调为“撤单已报”；
- 最终通过 `DoLevinGN_822` 确认为“买入、已撤”，`cdflag=1`、`kcdflag=0`、成交量为 0。

这次结果证明 `DoLevinGN_909` 和 `DoLevinGN_808` 的构造、回调关联及账户动态映射均可真机工作。
同时确认了一个柜台可见性窗口：报单回调成功不代表撤单入口已经能查到该笔委托。自动化流程必须先按
委托编号查询到唯一、可撤的记录，再发送撤单；第一次“没有对应的委托信息”不能触发重复报单。

   ```text
     -> 重新发起原业务请求
   ```

   业务请求本身不隐式触发登录。这样可以避免一次普通查询突然弹窗、提交密码或启动交易程序，也能让
   调用方明确决定等待、提示人工处理还是取消本次交易。需要为上述状态识别、HTTP 映射、单飞登录和
   登录完成后重试补充契约测试。
